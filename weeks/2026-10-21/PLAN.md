# 第 4 周：四周试运行收口与常态化判断 Implementation Plan

## Global Constraints

- 来源 p2 只读；固定 SHA 引用原件，不访问封存 test、不重开冻结阶段、不改现行研究队列或原始结果。
- 新增 GPU、训练、实验模型及裁判调用、付费 API、采购、标注、研究数据抽样与下载均为 0；CPU 累计最多 **2 core-hours**，不借用第三周或 p2 预算。
- 既有验收和工程回执直接复用；只检查影响本次结论的缺口。第四周不重新运行第二周枚举、第三周评分、旧 bootstrap 或全仓测试。
- 修正追加记录；候选、限定支持、独立确认、被修正和未检验分开，不用文件数或提交数判断成功。
- 公开材料仅引用版本化证据与有限读数；保持私有来源可达性说明，不将私有账本、逐目标标签或机器路径搬入公开仓库。
- 工作包编号不代表实际经过周数。报告注明实际起止日期、观察天数和尚未满足的延迟观察条件。

## Review Focus

1. 第三周只有计划或缺交付：T1 记录 NOT_DELIVERED，T4 输出部分收口，不给其编造数值或成功状态。
2. 第三周有执行回传但未验收：T1 标记 UNREVIEWED；T2 不将其主张升格为已支持。
3. 同缓存派生、合成真值或新增 seed 被当独立确认：T2 明确各自性质和独立性来源。
4. 评分运行耗时被当维护总成本、预算被当实耗：T3 分栏列数值与 UNKNOWN，避免重复加总。
5. 用户未作答或实际间隔不足：T3 保持相应未检验状态；T4 不报告个人迁移或长期保持效果。

## 2. T1：固定实际状态，不因缺少一项把整包停住

**接口：** 消费既有验收与第三周交付；产出 EVIDENCE_LEDGER 的输入版本／状态表，供后续全部判断使用。

- [ ] 检查经验仓库状态并保护用户已有改动；非 force 同步，固定本次材料提交 SHA、实际评估日期及周任务完成日期。
- [ ] 将每周区分为已验收、已交付未验收、未交付或有明确失败回传。第三周没有输出时，预先整理第 1、2 周和本周文档结构；正式回传记缺口，不把第三周 PLAN 写成结果。
- [ ] 第三周返回 INPUT_UNRESOLVED、NO_COUNTEREXAMPLE 或部分交付时照实纳入收口；不要求补做一个正结果。若没有独立第三周 REVIEW，第四周整理仍可完成，第三周主张保留待验收。
- [ ] EVIDENCE_LEDGER 给每项输入写仓库相对路径与固定 SHA；历史 p2 证据沿用已有准确定位，不另起一轮来源审计。

**检查：** 所有本月引用的读数都有实际文件；每个缺失或未验收项可被读者看见。只检查新增索引，不重跑旧实验。

## 3. T2：按主张修订经验，记录究竟哪里用到了

**接口：** 消费 T1 的版本与状态；产出最多五项有实际意义的主张、更新建议和真实用途证据，写入 EVIDENCE_LEDGER。

- [ ] 从阈值与比较、指标与任务证据、控制语义效度中选出实际有用或被修正的主张。每项写：准确主张、适用条件、支持／反证路径、证据性质、是否独立、实际使用、仍缺什么。
- [ ] 分开列第 2 周的合成评分反例和第 3 周的真实缓存复用；不得用二者认证对象 gold、真实方向机制、模型性能或独立数据确认。保留第 2 周 r1_misses 的字段更正及 R1 全真值定义的上限。
- [ ] 对“指导了真实决定”的记录，给出使用时间、使用者或任务、之前的可追溯方案、使用后的变化、相应交付指针。只有建议或原任务书已覆盖，就写建议／已覆盖；没有真实采用记录就写未观察，不推断防止了多少错误。
- [ ] 仅当已有验收支持明确的窄主张，且有实际复用／独立确认时，在对应条目末尾追加“限定支持”范围并进入 README 已支持索引。条目其他部分继续保留候选或缺口。第三周未验收时只给升格建议，不提前改已支持索引。

**检查：** 每项支持程度能从证据推出；README 与条目状态一致。全文允许已支持索引仍为空，不为了收口制造成熟经验。

## 4. T3：整理真实成本，准备一次个人迁移观察

**接口：** 消费前三周回执、使用记录及用户真实作答；产出 MONTH_REVIEW 的成本表和三项价值证据，个人反馈单独保存。

- [ ] 成本表按周分别列预算、可核对 CPU/GPU／实验模型调用实耗、实现验证与维护时间、记录范围及 UNKNOWN。单次运行与累计成本分列，禁止把第 2 周 0.0123 秒评分当整周成本、把第三周 4 core-hours 上限当实耗，或把未知当 0。
- [ ] 记录工具、案例或判断是否真正被复用，以及观察到的质量／决策变化。没有可比基线就不估计因果时间节约；文档数量和运行成功作为交付信息，不能单独证明项目收益。
- [ ] 准备两个新的短情境，分别考察公平比较和干预后的参考／读数选择，使用与原题不同的任务。用户建议投入 10 分钟以内；题目先固定，反馈要点分开保存，不在题面给答案。
- [ ] 有真实作答才按“可解释／可独立应用／有迁移证据”记录具体表现与遗漏；一轮作答不认证稳定掌握或教学因果效果。若没有作答，写未作答／未检验，继续执行。
- [ ] 仅在距首次相关真实作答至少 7 个自然日时，将新题标为本计划的延迟观察；否则记延迟条件未满足。该间隔是观察协议，非学习效果证明，不为等间隔而阻塞其他收口。

**检查：** 每个成本数可定位到原回执；个人状态有真实作答依据。MONTH_REVIEW 写明实际观察天数，不称已获得一个月或四周的保持效果。

## 5. T4：裁定价值、提出轻量后续并交付

**接口：** 消费 T1—T3；产出 MONTH_REVIEW、RETURN 和当前 README 入口。

- [ ] MONTH_REVIEW 首屏分别写三项判定：项目收益（真实决定／质量／成本变化）、经验复用（用过什么及有效范围）、个人掌握（真实独立判断）。每项用支持／部分支持／未观察／未检验并给证据，不合并成一个总 PASS。
- [ ] 给一个明确的过程建议及依据：有实际用途且维护负担可承担时继续限定范围；主要仍是合成演示、重复整理或用途未观察时收缩为“随真实研究追加短案例”；来源长期不可用或实测负担妨碍主研究且缺少用途时暂停专门维护包。成本或收益证据不足就注明建议暂定，保留恢复／改变判断所需的新证据。
- [ ] 形成下一周期最多两个候选、一个推荐：默认候选 A 为“在一个已经授权的真实研究任务中记录并复用一条经验”，候选 B 为“有用户参与的独立迁移与延迟复盘”。按实测用途、缺口和负担排序；推荐可以是只做轻量记录。各候选说明来源、能影响哪个选择、最小验证和停止条件，不扩展成新主模型阶段或自动授权训练。
- [ ] 若继续或收缩，写最小常态化方式：真实实验里一次短记录，包含问题／原预测／结果／边界／下一步；仅发现重要新用途或修正时形成完整案例，按月集中回传。若暂停，保留现有资产与重启条件，不删除历史。
- [ ] RETURN 沿用原九项格式，首屏列三项判定、一个推荐、第三周是否验收及实际成本。第三周仍未交付时使用 MONTH_REVIEW_PARTIAL，完整解释观察范围；其他可执行工作照常交付。
- [ ] 进行一次新增链接、SHA、状态和公开范围检查；提交并推送 main，确认远端，最终回传 RETURN／MONTH_REVIEW 路径和真实 40 位交付 SHA。不在该提交文件内自引用其尚未产生的 SHA。

**验收：** 读者可以据真实证据决定这套方式接下来保留什么、收缩什么、等待什么；至少明确了实际用途或定位了无法判断的缺口。未答练习不阻塞交付，个人掌握仍独立标未检验。

## 6. 节奏与停止

第三周执行期间可先整理已有材料；收到它的真实 RETURN 后，用第一个执行日完成 T1/T2，第二个执行日完成 T3/T4。准备也记录成本，等待输入不重置 72h 计时。无需等名义周日期或日常逐项审批。没有用户作答也要交付客观部分。

72h、CPU 2 core-hours 或日期上限先到即停止剩余操作，保留已完成交付与缺口；不靠新实验补齐。第四周只作试运行过程判断。后继科学实验的授权仍由对应研究任务书明确给出。
