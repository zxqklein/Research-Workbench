# Research Workbench Weekly Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task when that skill is available. Steps use checkbox (`- [ ]`) syntax for tracking. Preserve the user's existing local-controller execution method. A missing skill on another execution platform must be reported; it does not authorize changing the evidence or approval boundaries.

**Goal:** 用四周试运行，建立可追溯的经验仓库，完成一次外部做法的本地验证和一次复用，并分别记录项目收益与个人掌握证据。

**Architecture:** 过程案例与经验手册互相引用，个人练习单独记录；每周集中回传。来源项目保留原始代码和实验结果，独立经验仓库保存条件、判断、证据定位与修正历史。

**Tech Stack:** Markdown、Git；仅在具体经验实验需要时复用来源项目的运行环境，不为文档维护新增框架。

**Spec:** 配套文件 `2026-09-30-research-workbench-design.md`；入仓位置为 `docs/superpowers/specs/2026-09-30-research-workbench-design.md`。本任务书第 1 节也复述执行所必需的边界，交接时请同时提供两份文件。

状态：设计定位已由用户确认；本轮交付为任务安排，未声称 GitHub 仓库或后续实验已经执行。

## Global Constraints

- 仓库暂名 `research-workbench`；采用独立仓库，来源项目保持只读。
- p2 来源读取 `zxqklein/p2` 的 `feat/c1-directional-delta-v1` 分支，先固定完整提交 SHA。
- 原始预测与实验结果保持不变；修正追加记录，复算产物另存。
- 历史记录没有事前预测时写明缺失；用户作答只能来自用户实际输入。
- 指标、任务能力、机制、工程正确性和个人掌握分别报告。
- 不访问锁定 test、不重开冻结阶段、不启动未定义的完整训练。
- 第一周不启动新增 GPU 训练；后续预算由问题和实测小试成本决定。
- 每周围绕一个主要问题；提前完成可以执行本周预定义补充，不能自行扩展成新的主模型阶段。

## Review Focus

1. 摘要替代原件：每项科学主张必须能定位到已核对的版本化证据，任务 1 检查。
2. 回顾性解释冒充事前预测：检查历史记录的时间与来源，任务 1 检查。
3. 干预改变正确答案：比较前明确预期答案关系，任务 2 检查。
4. 探索污染确认：独立确认不得继续使用同一批已用于筛选的信息，任务 3 检查。
5. 报告产量冒充个人掌握：只有真实独立作答与迁移反馈支持掌握程度，任务 1 和任务 4 检查。

本文以内容和证据交付为主，不为 Markdown 创建、排版或模板复制编写单元测试。实验代码采用能检查实际读数、分组或关键行为的必要验证。

## 1. 工作方式与四周安排

沿用本地主控与执行模型：本地负责资料定位、实现、运行和产物；每周形成一次供科学判断的回传。用户约用 20—30 分钟完成几项关键预测和复盘；没有及时作答时，不阻塞客观整理，个人掌握程度保持“未检验”。

| 周期（北京时间） | 本周主问题 | 核心交付 | 验收依据 |
|---|---|---|---|
| 第 1 周：09-30—10-06 | 已有实验究竟形成了哪些有条件的经验？ | 独立仓库初稿、三个历史候选案例、相应经验条目和首轮练习 | 主张可追溯，预测与事后解释分清，缺口诚实保留 |
| 第 2 周：10-07—10-13 | 一项外部做法能否解决当前具体问题？ | 一个固定问题、一份事前方案、一次低成本验证 | 对照能回答问题，收益与代价可测，保留负结果 |
| 第 3 周：10-14—10-20 | 上周经验在新条件下是否仍有用？ | 一次独立确认或复用、适用边界更新、用户独立判断 | 明确新条件与独立性，不把新增 seed 当作跨任务迁移 |
| 第 4 周：10-21—10-27 | 这套方式是否值得常态化？ | 月回传、修订后的经验索引、下一月候选 | 项目收益、复用价值、个人掌握分别裁定 |

第 1 周为确定的执行任务。第 2—4 周的方向和交付合同固定，具体实验依据前一周证据按本文选择规则确定；当前不虚构尚未观察到的瓶颈、样本或训练预算。

### 问题选择规则

默认优先验证首周形成的**评估或公平比较做法**。选择须同时满足：有当前真实问题；主要变化因素能隔离；结果可可靠测量；对当前决策有影响；数据和操作在既有授权范围内。合格候选按“当前决策影响、可识别性、少量交互可完成、成本”顺序排序，只选择一个。

候选不合格时，记录具体缺少的观测条件，利用现有读数完成可回答的部分；不得改成漫无目的的模型或参数搜索。

- [ ] 实验前固定主要问题、最强竞争解释、唯一主要干预、比较对象、读数、最小实际收益或决策条件、停止条件。作者预测与 AI 预测分别保存；作者未参与不伪造。
- [ ] 若是行为测试，先写清干预后正确答案应保持还是应改变；只有预期关系可核对的样本进入该项读数。变化后的真实语义不能被当作保持标签不变的对照。
- [ ] 若是公平比较，明确比较的是直接替换效果还是相当调优预算下的效果；相应固定或分别优化配套参数，记录失败配置和消耗。
- [ ] 先运行最低成本的可判别验证，再依 PLAN.md 决定是否增加确认。若需要新增训练，先用短小试测吞吐、显存和单位成本，再把种子数、训练步数、总 GPU-hours 预算固定到方案中；本任务不自动授权完整新模型训练。
- [ ] 保存所有计划内结果，按事前条件解释。失败、零收益和环境阻塞都按真实原因记录，不自动升级为经验。
- [ ] 形成一个有条件的条目及下一周确认对象，记录作者的新案例判断或未参与状态。

**验收条件：** 得到一个能改变后续选择的判断，或明确定位使本题无法识别的缺口；不得只交付一个“最高分配置”。

## 6. 每周固定回传格式

`RETURN.md` 保持便于一次阅读，可将原始读数另链。字段为：

1. 本周问题与来源提交。
2. 实际完成任务和新增产物。
3. 三项以内关键证据与来源。
4. 结论、竞争解释和限制。
5. 可复用经验及其证据程度。
6. 作者真实预测、作答和掌握状态。
7. 实际 CPU/GPU 消耗与维护时间。
8. 下周候选、排序和推荐。
9. 未完成事项和具体原因。

用户不需要每天交互。执行者在计划内自行推进，集中回传必要科学问题；不会因为缺少一次个人练习作答而停止已有授权的客观工作。
