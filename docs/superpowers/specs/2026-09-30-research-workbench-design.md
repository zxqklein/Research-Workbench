# Research Workbench：经验仓库设计说明

版本：1.0；日期：2026-09-30；时区：Asia/Shanghai。

用户已确认的定位：建立独立的开源仓库，保留研究经验和积累经验的过程。用户随后要求按周安排任务。本文件将该定位具体化，供第一周执行时与任务书一起阅读。

## 1. 目的和成功标准

仓库暂名 `research-workbench`，服务于作者自己的研究判断、方法使用和跨问题迁移，同时为其他研究者提供可追溯的案例。

每个案例应使读者看清：问题是什么，为什么借鉴某个方法，原先怎样预测，实际看到了什么，哪些解释被排除，哪些仍未排除，以及下一次该怎样行动。

试运行的成功不按文档数或实验数判断，而按以下三个结果判断：至少一条记录能指导后续决策；至少一次复用得到实际反馈；作者对一个新案例的独立判断能够被检验。三个结果分别报告，可以分别成立或不成立。

## 2. 内容组织

| 路径 | 职责 |
|---|---|
| `README.md` | 用途、阅读入口、经验索引、当前问题和证据可达性说明 |
| `AGENTS.md` | AI 执行规则：来源追溯、记录边界、原始结果保护、回传格式 |
| `cases/` | 按问题保存经验形成的过程，包含结果和修正记录 |
| `playbook/` | 提炼可复用的做法，注明条件、成本、失效情形并回链案例 |
| `practice/` | 原创的新案例练习、作者实际作答和后续反馈 |
| `templates/` | 案例、经验条目、练习和周回传的简短模板 |
| `weeks/YYYY-MM-DD/` | 从该日期开始的七天周期之计划、产物索引和回传 |
| `LICENSE` | 发布时采用的许可；任务书给出可修改的默认建议 |

初期以中文 Markdown 为主。可执行工具只有在某个案例确实需要时才添加。实验代码、模型权重和大产物由来源项目保存，经验仓库记录其位置和版本。

## 3. 案例与经验条目

案例必须包含：问题与情境；外部做法及来源；假设与竞争解释；实验前预测；操作及比较条件；结果和证据；支持与不支持的结论；修正记录；下一步行动。

历史案例的预测只能从当时留下的记录提取。原记录没有预测时，写明“未找到事前预测记录”；现在提出的解释标为“回顾性解释”。不能将 AI 的预测或总结写成用户曾经的想法。

经验条目至少包含：触发条件；推荐行动及理由；成本；不适用或失效情形；证据链接及核对状态；后续复用记录。

每项主张单独记录证据程度：`候选`、`本地支持`、`独立复核`、`被修正`。同一案例内不同主张可以处于不同程度；发现修正不意味着旧案例全部无效。独立复核必须说明它与探索过程在哪些信息或条件上独立。

## 4. 证据边界

来源项目为 `zxqklein/p2` 时，读取 `feat/c1-directional-delta-v1` 分支，先固定完整提交 SHA；遵守该版本适用的 `AGENTS.md` 和工作流要求。来源仓库保持只读；新增经验实验在独立位置运行。

科学主张关联实际核对的文件、提交、原始读数和适用范围。对话摘要和记忆只用于寻找原件。本文不宣称已核对 p2 当前分支或全部历史原始结果。

原始结果和当时的预测记录保留不变。更正以追加说明或单独派生结果体现。工程检查通过、指标提高、机制得到支持和任务能力得到支持分别陈述。

探索所得的最佳设置需要适当的独立确认。新增 seed 可以检查同配置的稳定性，不能单独证明跨任务或跨数据条件迁移。持续使用同一开发集筛选所得结论不得被表述为独立确认。

## 5. 作者参与与自动执行

沿用现有分工：本地主控处理资料定位、实现、运行、结果整理和一致性检查；科研判断以证据为依据，重大方向选择集中在周回传中讨论。

作者每周预留约 20—30 分钟，完成简短预测、新案例判断和复盘。这是建议时间，不是实验启动的逐项授权门槛。作者暂时未参与时，允许继续已布置的客观整理和实验，个人掌握程度写为“未检验”。

作者的掌握记录分别使用 `未检验`、`可解释`、`可独立应用`、`有迁移证据`，并关联实际作答。阅读一篇报告不自动改变掌握记录。

## 6. 周期和资源

首轮为四个连续七天周期：2026-09-30—10-06、10-07—10-13、10-14—10-20、10-21—10-27。日期是验收窗口，任务可提前完成；不得为了占满一周而制造无关工作。

每周围绕一个主要问题安排工作。第一周不启动新增 GPU 训练；必要的历史读数复算注明目的和消耗。后续 GPU 预算随所选问题的可识别性和实际小试耗时确定，不预设必须使用三张卡，也不以消耗额度作为目标。

本试运行不授权改写 p2 冻结结果、访问锁定 test、重开冻结阶段或启动未定义的完整模型训练。

## 7. 周回传

每周的 `RETURN.md` 包含：本周问题；来源提交；实际完成内容；关键证据；结论与限制；可复用经验；个人掌握证据；实际资源消耗；下一周候选与推荐；尚缺信息。

日期、文件数、可用样本数、训练次数和时间均记录实测值。环境、来源或权限阻塞时完成不依赖该条件的工作，集中回传阻塞；不靠猜测填满交付数量。

开源记录中说明证据是否公开可达。未公开的原件可保留准确内部定位，但公开页面不得把它宣称为任何读者都能复现的证据。

## 8. 首批案例和试运行边界

首批候选来自此前讨论中的三个问题：阈值调整与公平比较；文本指标与视觉事实读数；输入干预是否改变正确答案。三者须重新定位原文件后才能形成有证据的经验条目。

如果首周发现某个候选缺少关键证据，保留其缺口并降低主张范围；只有实际形成可用经验的案例进入手册索引。四周后按项目收益、经验复用和个人掌握分别作继续、调整或暂停判断。
