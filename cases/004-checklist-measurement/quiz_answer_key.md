## 1. 能否通过 R0？——**能，16/16 ＋ 64/64 满分通过**

- 变化组换序关系：它忽略标记，两个提示版本下输出相同：AB（A→B）恒答 APPEAR、BA（B→A）恒答 DISAPPEAR，方向性成立且互为反向 → 16 配对全过。
- AA/BB：两帧同 ID → 判空 → 64 条全过。
- 通过方式与 INVERT_TARGET 同类：它对"先 A 后 B"这一输入身份模式有固定方向先验，恰好在变化组上与真值一半重合、且两顺序答案天然反向。

## 2. R1 哪个组件捕获、哪个不捕获？

逐格推出的仪表表（对比 SLOT_ID，两者 MFT 同为 80/128 但错行构成不同）：

| 组件 | PHASE_CONFUSER | SLOT_ID（实测） |
|---|---|---|
| MFT /128 | 80（错 48：无变化组 AB/BA 32 行＋(1,0) 组变化行 16 行） | 80（错 48：无变化组 AB/BA 32 行＋**另一半**变化行 16 行） |
| 联合 AB+BA /32 | 8（仅 (0,1) 组） | 8 |
| DIR 关系 /16 | 16 | 16 |
| DIR 变化行正确 /32 | 16 | 16 |
| **INV /64** | **64（满分——不被捕获）** | **32（被捕获）** |
| AA/BB 判空 /64 | 64 | 64 |

- **捕获它的是逐条件 MFT（含 DIR 的"答案正确"分列）**：(1,0) 的 4 个组上它答 APPEAR/DISAPPEAR 而真值相反，无变化组 AB/BA 上真值是判空它却答方向。
- **不捕获它的是提示不变性 INV**：它不理会标记，两版本答案永远相同——版本稳定 ≠ 方向正确。这正是 INVERT_TARGET 的同款盲区：INV 对"输入身份驱动但与标记无关"的捷径无效。

## 3. 与哪个真实反例最接近？

**SLOT_ID**。PHASE_CONFUSER 在提示版本 0 下与 SLOT_ID 的输出逐条相同（SLOT_ID 在 v0 被标记推到同样的答案）；差别全部由标记通道造成：SLOT_ID 在 v1 翻转 → 产生 INV 失败与另一半错行，PHASE_CONFUSER 版本稳定 → INV 满分但方向照错。两者的 MFT 同为 80/128、联合同为 8/32——**INV 的得失不改变 MFT 层面的失败**。

## 4. 最少还需要什么信息才能通过 R1？

只补"顺序标记"不够（那就是 SLOT_ID，仍 80/128）。它必须能读到**目标在实际两帧中的存在性**（并按方向规则使用）——即变成 ORACLE 才能过 R1。这说明完整合同里最不可删的组件是**逐条件正确目标读数（MFT/DIR 正确性）**：输入身份、顺序标记、同图判空、版本不变性都可以在完全不接触目标状态的情况下满分，唯有逐条件正确性直接绑定"方向判断本身"。对应到未来真实方向实验：关系测试与不变性测试只能当必要行为证据，接收判据必须含逐条件正确目标分。
